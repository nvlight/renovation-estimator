# Расчёты

Интерактивные формулы ниже реализованы **на клиенте** (Vue computed). API сохраняет уже готовые `sum` / `amount` / `more_info`; сидеры рассчитывают собственные демонстрационные значения на сервере.

Единицы:

- длина стены в БД и UI — **сантиметры**;
- высота комнаты — **метры**;
- периметр и площади в смете — **метры / м²**.

## Геометрия контура

Стена — вектор:

- `length` — длина, см;
- `angle` — направление в градусах от оси X, против часовой;
- `is_real` — `1` стена, `0` проём.

Обход: старт `(0, 0)` (для площади) или смещённый центр SVG (для чертежа).

```
x += (length / 100) * cos(angle * π / 180)
y += (length / 100) * sin(angle * π / 180)   // для площади, метры
```

На SVG длина масштабируется `× 0.2`, ось Y инвертирована (`y -= dy * 0.2`).

### Замкнутость

На чертеже конец сравнивается со стартом в «сантиметрах чертежа»:

```
dx = (end.x - start.x) / 0.2
dy = (start.y - end.y) / 0.2
is_closed = |dx| < 1 && |dy| < 1
```

Незамкнутый контур нельзя сохранить. API это не проверяет.

### Периметр

```
perimeter_m = Σ length_i / 100
```

Проёмы (`is_real = 0`) **входят** в периметр (это длина контура), но могут исключаться из площади стен.

### Площадь стен (шапка спецификации)

```
wallsSquare = perimeter_m × height_m
```

Проёмы не вычитаются.

### Площадь потолка и пола

Формула шнурков (Гаусса) по вершинам в метрах:

```
area = ½ | Σ (x_i y_{i+1} − x_{i+1} y_i) |
```

Результат округляется до 2 знаков. Пол в UI равен потолку (отдельной геометрии пола нет).

Внутренний угол в вершине (подписи SVG) — угол между векторами к соседям, `acos(dot / (|v1||v2|))`.

### Количество полотна

```
processedCeilingSquare = max(10, ceil(area_m2))
```

Меньше 10 м² всё равно считается как 10.

### Багеты (периметр)

```
val = ceil(perimeter_m)
если val нечётный → val += 1
val += 2   // запас
```

Цена багета: **55 ₽/м**.

### Прочие строки (редактируемый count)

| Позиция | Цена по умолчанию | Count по умолчанию |
|---|---|---|
| Люстры | 200 | 1 |
| Светильники | 150 | 0 |
| Вставка | 30 | 0 |
| Трубы | 150 | 0 |
| Доставка | 1000 | 1 |

Сумма строки: `count × price`. Итог — сумма всех строк.

«Добавить работу» пишет `RoomJob`:

```json
{
  "room_id": "<id>",
  "title": "Натяжной потолок",
  "sum": "<total>",
  "more_info": [ { "name", "amount", "price", "sum" }, ... ]
}
```

В `more_info` попадают только строки с `count > 0`.

Калькулятор материалов к натяжному (`StretchCeilingBuildingMaterials.vue`) — черновик: шаги крепежа и таблица по id, **в смету комнаты не пишет**.

Длины стен в калькуляторе можно временно поменять (поля «Стена N») и сбросить к эталону.

## Гипсокартон — работы

Файл: `DrywallCalc.vue`. Ставка: **`pricePerSquareMeter = 600` ₽/м²**.

### Площади

```
perimeter_m           = Σ length / 100
ceilSquare            = shoelace(стены)
wallsSquare           = perimeter_m × height          // все сегменты
improvedWallsSquare   = (Σ length where is_real=1) / 100 × height
```

Чекбоксы `counting.ceil` / `counting.walls`. Кнопки ± м² отдельно для потолка и стен (`incDecSquareMetersForCeil/Walls`).

```
ceilSquareSum  = round(ceilSquare) × 600  + 600×inc − 600×dec   (≥ 0, ceil)
wallsSquareSum = round(improvedWallsSquare) × 600 + 600×inc − 600×dec  (≥ 0, round)
totalDrywallSum = (ceil ? ceilSquareSum : 0) + (walls ? wallsSquareSum : 0)
```

«Добавить работу» создаёт **одну или две** записи `RoomJob`:

- title `Гипсокартон, потолок`;
- title `Гипсокартон, стены`.

Кнопка активна, если выбран хотя бы потолок или стены.

В `more_info.amount` записывается округлённая исходная площадь. Ручная поправка ± м² меняет `sum`, но не это поле `amount`.

## Гипсокартон — материалы потолка

`DrywallBuildingMaterialsForCeil.vue`. Выходные строки жёстко завязаны на **id справочника**:

| id | Смысл | Основа расчёта |
|---|---|---|
| 3 | Потолочный профиль | длина 3 м, шаг линий 0.4 м |
| 4 | Направляющий профиль | длина 3 м, нахлёст 0.2 м |
| 5 | Прямой подвес | шаг 0.5 м |
| 11 | Саморез по дереву | шаг 0.2 м по направляющим + 4 на подвес |
| 14 | Саморез «семечка» | соединения профиля |
| 15 | Дюбель-гвоздь | шаг 0.4 м по направляющим + 3 на подвес |

В `materialsInputs` также объявлены id 6 и 16, но текущий `ceilMaterials` их в итоговую таблицу не включает.

Количество направляющих считается от периметра, длины профиля и стыка. Количество потолочного профиля — от габаритов прямоугольника, описанного вокруг контура (`maxCeilLength` / `maxCeilWidth`) и шага 0.4 м. Подвесы — от длины профилей и шага 0.5 м.

Если в `title` материала есть `N шт`, цена упаковки делится с учётом фасовки (`getMaterialTotalSum`).

Таблица: id, title, amount, price, sum. Можно добавить одну строку или все сразу в `room_materials`.

`DrywallBuildingMaterials.vue` показывает блок потолка только при `isCountingCeil`. Блок стен (`DrywallBuildingMaterialsForWalls.vue`) **не подключён** в шаблон обёртки.

## Гипсокартон — материалы стен (черновик)

`DrywallBuildingMaterialsForWalls.vue` выводит черновую таблицу для id `[11, 6, 15, 16, 28]` (саморезы, дюбели, лента). Константа `[11, 14, 15, 28]` в файле не используется. Компонент не подключён к обёртке и в смету не интегрирован.

## Что не считается

- Двери и окна как отдельные проёмы с площадью (есть только `is_real` у сегмента стены).
- Шпатлёвка, покраска, пол, электрика — вкладок/формул нет.
- Сервер не пересчитывает смету при изменении стен: нужно заново прогнать калькулятор и добавить новые `RoomJob` / `RoomMaterial` (старые позиции сами не обновляются).
